راهنمای نصب و راه‌اندازی Kitty Terminal

این راهنما بر اساس تجربه واقعی نصب Kitty روی اوبونتو (GNOME, Wayland) نوشته شده و مشکلاتی که در این مسیر پیش اومد و راه‌حل‌شون رو پوشش می‌ده.

۱. نصب Kitty

نصب با اسکریپت رسمی نصب انجام شد:

curl -L https://sw.kovidgoyal.net/kitty/installer.sh | sh /dev/stdin

این دستور Kitty رو در مسیر زیر نصب می‌کنه:

~/.local/kitty.app/
مشکل: این روش نصب، باینری Kitty رو به PATH سیستم اضافه نمی‌کنه. یعنی دستور kitty به‌تنهایی در ترمینال کار نمی‌کنه و باید از مسیر کامل استفاده بشه: 
/home/pc1/.local/kitty.app/bin/kitty

۲. تغییر نام تب (Rename Tab)

برخلاف GNOME Terminal، در Kitty یک کلید میانبر پیش‌فرض برای این کار وجود داره، ولی در فایل کانفیگ پیش‌فرض به‌صورت کامنت‌شده (غیرفعال) قرار داره:

# map --allow-fallback=shifted,ascii kitty_mod+alt+t set_tab_title

مقدار پیش‌فرض kitty_mod برابر ctrl+shift هست، یعنی کلید میانبر نهایی Ctrl+Shift+Alt+T می‌شه.

راه‌حل: فعال‌سازی دستی

mkdir -p ~/.config/kitty
echo "map ctrl+shift+alt+t set_tab_title" >> ~/.config/kitty/kitty.conf

بعد از این کار، Kitty رو ری‌استارت کن (یا با Ctrl+Shift+F5 کانفیگ رو reload کن). حالا با زدن Ctrl+Shift+Alt+T یک پرامپت پایین صفحه باز می‌شه که می‌تونی اسم جدید تب رو بنویسی.

✓ تست شد و با موفقیت کار کرد.

۳. اضافه کردن Kitty به نوار Favorites (GNOME)

بعد از نصب، Kitty در جستجوی Activities پیدا نمی‌شد و در نتیجه امکان "Add to Favorites" هم نبود. علت این بود که نصب‌کننده، فایل .desktop رو فقط داخل پوشه نصب می‌ذاره، نه در مسیری که GNOME اسکن می‌کنه.

مرحله ۱ — کپی فایل‌های desktop

cp ~/.local/kitty.app/share/applications/kitty.desktop \
   ~/.local/kitty.app/share/applications/kitty-open.desktop \
   ~/.local/share/applications/

مرحله ۲ — اصلاح مسیرها

فایل‌های desktop به‌صورت پیش‌فرض از نام‌های نسبی (kitty) استفاده می‌کنن که چون باینری در PATH نیست، باید به مسیر کامل تغییر کنن:

کلیدمقدار قبلیمقدار اصلاح‌شده
Execkitty/home/pc1/.local/kitty.app/bin/kitty
Iconkitty/home/pc1/.local/kitty.app/share/icons/hicolor/256x256/apps/kitty.png
TryExeckitty/home/pc1/.local/kitty.app/bin/kitty
نکته مهم (دلیل اصلی مشکل): اصلاح Exec و Icon به‌تنهایی کافی نبود. کلید TryExec هم باید اصلاح بشه چون GLib/GIO (موتوری که GNOME Shell برای جستجوی اپ‌ها استفاده می‌کنه) اگر مسیر TryExec پیدا نشه، کل entry رو به‌طور کامل نادیده می‌گیره — نه فقط مخفی می‌کنه، بلکه از لیست Gio.AppInfo.get_all() هم حذفش می‌کنه. این باگ ظریف، دلیل اصلی بود که حتی بعد از کپی فایل desktop، Kitty در جستجو ظاهر نمی‌شد.

مرحله ۳ — به‌روزرسانی دیتابیس

update-desktop-database ~/.local/share/applications

مرحله ۴ — تایید

برای اطمینان از اینکه GNOME واقعاً اپ رو می‌بینه (بدون نیاز به باز کردن منو):

python3 -c "
import gi
gi.require_version('Gio', '2.0')
from gi.repository import Gio
for a in Gio.AppInfo.get_all():
    if 'kitty' in a.get_id().lower():
        print(a.get_id(), '|', a.get_name(), '|', a.get_commandline())
"
نکته درباره Wayland: چون نشست GNOME از نوع Wayland بود، روش قدیمی ری‌استارت GNOME Shell با Alt+F2 → r کار نمی‌کنه (این فقط روی X11 جواب می‌ده). در عمل، بعد از اصلاح TryExec، GNOME Shell بدون نیاز به logout دوباره فایل‌ها رو شناسایی کرد. اگر در حالت مشابه جواب نداد، راه‌حل قطعی خروج و ورود مجدد (logout/login) هست.
✓ بعد از این مراحل، Kitty در جستجوی Activities ظاهر شد و امکان Add to Favorites فراهم شد.

خلاصه دستورات

# نصب
curl -L https://sw.kovidgoyal.net/kitty/installer.sh | sh /dev/stdin

# فعال‌سازی rename تب
mkdir -p ~/.config/kitty
echo "map ctrl+shift+alt+t set_tab_title" >> ~/.config/kitty/kitty.conf

# یکپارچه‌سازی با دسکتاپ
cp ~/.local/kitty.app/share/applications/kitty.desktop \
   ~/.local/kitty.app/share/applications/kitty-open.desktop \
   ~/.local/share/applications/

sed -i "s|Exec=kitty|Exec=/home/pc1/.local/kitty.app/bin/kitty|g; \
        s|TryExec=kitty|TryExec=/home/pc1/.local/kitty.app/bin/kitty|g; \
        s|Icon=kitty|Icon=/home/pc1/.local/kitty.app/share/icons/hicolor/256x256/apps/kitty.png|g" \
        ~/.local/share/applications/kitty.desktop ~/.local/share/applications/kitty-open.desktop

update-desktop-database ~/.local/share/applications
