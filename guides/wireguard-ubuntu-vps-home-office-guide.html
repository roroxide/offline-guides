۱. معماری و آدرس‌دهی

VPS دارای IP عمومی است و نقش Hub را دارد. خانه و شرکت هر دو اتصال خروجی WireGuard به VPS برقرار می‌کنند؛ بنابراین برای خانه IP ثابت یا Port Forwarding مودم لازم نیست.

Office (10.50.0.3) ── UDP/51820 ──► VPS (10.50.0.1) ◄── UDP/51820 ── Home (10.50.0.2)
                              WireGuard hub
Office ───────────────────────► VPS ───────────────────────────► Home
                         SSH / RDP over VPN
نقشآدرس تونلمشخصات
VPS10.50.0.1/24IP عمومی نمونه: 185.36.145.173، پورت UDP 51820
خانه (مقصد)10.50.0.2/24سرور SSH و ریموت دسکتاپ
شرکت (مبدأ)10.50.0.3/24کلاینت SSH و ریموت دسکتاپ
توجه: IP عمومی بالا متعلق به سناریوی نمونه است؛ برای استقرار جدید آن را با IP یا دامنه VPS خود جایگزین کنید. هر سه IP خصوصی باید یکتا باشند. این مستند کلید خصوصی واقعی را شامل نمی‌شود.

۲. پیش‌نیازها در هر سه سیستم

دستورات زیر را جداگانه روی VPS، خانه و شرکت اجرا کنید:

sudo apt update
sudo apt install -y wireguard wireguard-tools iproute2 iputils-ping

بررسی نصب:

wg --version
ip -br addr

روی VPS پورت 51820/udp را در فایروال سیستم و پنل ارائه‌دهنده VPS مجاز کنید. اگر UFW فعال است:

sudo ufw allow 51820/udp
sudo ufw status
اگر مدیریت VPS از راه دور انجام می‌شود، قبل از تغییر سیاست فایروال، دسترسی SSH مدیریتی خود را حفظ کنید. برای اتصال از شرکت به خانه، نیازی به باز کردن پورت ۲۲ یا ۳۳۸۹ روی IP عمومی VPS نیست.

۳. ساخت کلیدهای WireGuard و مشاهده آن‌ها

روی هر سه سیستم، جداگانه یک جفت کلید بسازید. کلید خصوصی هر سیستم فقط روی همان سیستم باقی بماند:

sudo install -d -m 700 /etc/wireguard
sudo sh -c 'umask 077; wg genkey > /etc/wireguard/private.key'
sudo sh -c 'wg pubkey < /etc/wireguard/private.key > /etc/wireguard/public.key'
sudo chmod 600 /etc/wireguard/private.key /etc/wireguard/public.key

دستور نمایش کلید عمومی

sudo cat /etc/wireguard/public.key

اگر فایل public.key موجود نبود، می‌توان کلید عمومی را مستقیماً از کلید خصوصی استخراج کرد:

sudo wg pubkey < /etc/wireguard/private.key

دستور نمایش کلید خصوصی

sudo cat /etc/wireguard/private.key
هشدار امنیتی: دستور آخر کلید خصوصی را نمایش می‌دهد؛ فقط در ترمینال مطمئن استفاده کنید. کلید خصوصی را در پیام، اسکرین‌شات، مخزن Git یا فایل اشتراکی منتشر نکنید. هنگام وارد کردن آن در wg0.conf از مقدار واقعی همان دستگاه استفاده کنید.

جمع‌آوری کلیدهای عمومی برای پیکربندی

دستگاهدستور روی همان دستگاهنامی که در تنظیمات استفاده می‌شود
VPSsudo cat /etc/wireguard/public.keyVPS_PUBLIC_KEY
خانهsudo cat /etc/wireguard/public.keyHOME_PUBLIC_KEY
شرکتsudo cat /etc/wireguard/public.keyOFFICE_PUBLIC_KEY

برای مقدار PrivateKey هر دستگاه نیز از دستور sudo cat /etc/wireguard/private.key روی همان دستگاه استفاده کنید. رشته‌های نمونه در بخش‌های بعدی باید با خروجی واقعی جایگزین شوند؛ علامت‌های < و > نباید در فایل نهایی باقی بمانند.

۴. پیکربندی VPS (Hub)

فایل تنظیمات را ایجاد کنید:

sudo nano /etc/wireguard/wg0.conf

محتوای نمونه:

[Interface]
Address = 10.50.0.1/24
ListenPort = 51820
PrivateKey = <VPS_PRIVATE_KEY>
MTU = 1280

# Allow traffic between WireGuard peers (including when Docker uses FORWARD DROP)
PostUp = iptables -C FORWARD -i %i -o %i -s 10.50.0.0/24 -d 10.50.0.0/24 -j ACCEPT || iptables -I FORWARD 1 -i %i -o %i -s 10.50.0.0/24 -d 10.50.0.0/24 -j ACCEPT
PostDown = iptables -C FORWARD -i %i -o %i -s 10.50.0.0/24 -d 10.50.0.0/24 -j ACCEPT && iptables -D FORWARD -i %i -o %i -s 10.50.0.0/24 -d 10.50.0.0/24 -j ACCEPT || true

[Peer]
# Home
PublicKey = <HOME_PUBLIC_KEY>
AllowedIPs = 10.50.0.2/32

[Peer]
# Office
PublicKey = <OFFICE_PUBLIC_KEY>
AllowedIPs = 10.50.0.3/32
چرا /32؟ روی VPS، هر Peer باید تنها IP تونل خودش را در AllowedIPs داشته باشد. اختصاص یک شبکه یکسان به هر دو Peer می‌تواند مسیریابی را خراب کند.

مجوز فایل و فعال کردن Forwarding دائمی:

sudo chmod 600 /etc/wireguard/wg0.conf
echo 'net.ipv4.ip_forward=1' | sudo tee /etc/sysctl.d/70-wireguard.conf
sudo sysctl --system
sysctl net.ipv4.ip_forward

مقدار مورد انتظار: net.ipv4.ip_forward = 1.

اگر روی VPS Docker فعال است، زنجیره FORWARD ممکن است سیاست DROP داشته باشد. قوانین PostUp/PostDown بالا فقط ترافیک بین Peerهای WireGuard را مجاز می‌کنند؛ کل فایروال را باز نمی‌کنند. اگر مدیریت فایروال با nftables خالص یا ابزار دیگری انجام می‌شود، باید قانون متناظر آن ابزار را تنظیم کنید.

۵. پیکربندی سیستم خانه (مقصد)

sudo nano /etc/wireguard/wg0.conf
[Interface]
Address = 10.50.0.2/24
PrivateKey = <HOME_PRIVATE_KEY>
MTU = 1280

[Peer]
PublicKey = <VPS_PUBLIC_KEY>
Endpoint = 185.36.145.173:51820
AllowedIPs = 10.50.0.0/24
PersistentKeepalive = 25
sudo chmod 600 /etc/wireguard/wg0.conf

PersistentKeepalive = 25 برای خانه‌ای که پشت NAT و IP متغیر است مفید است. مقدار AllowedIPs فقط ترافیک شبکه VPN را وارد تونل می‌کند، نه تمام اینترنت را.

۶. پیکربندی سیستم شرکت (مبدأ)

sudo nano /etc/wireguard/wg0.conf
[Interface]
Address = 10.50.0.3/24
PrivateKey = <OFFICE_PRIVATE_KEY>
MTU = 1280

[Peer]
PublicKey = <VPS_PUBLIC_KEY>
Endpoint = 185.36.145.173:51820
AllowedIPs = 10.50.0.0/24
PersistentKeepalive = 25
sudo chmod 600 /etc/wireguard/wg0.conf
خطای تجربه‌شده: اگر اشتباهاً روی خانه آدرس 10.50.0.3/24 بگذارید، سیستم خانه IP شرکت را محلی تلقی می‌کند و ارتباط بین دو سیستم خراب می‌شود. روی خانه فقط 10.50.0.2/24 و روی شرکت فقط 10.50.0.3/24 تنظیم کنید.

۷. راه‌اندازی، فعال‌سازی دائمی و بررسی

ابتدا روی VPS و سپس روی خانه و شرکت اجرا کنید:

sudo systemctl enable --now wg-quick@wg0
sudo systemctl status wg-quick@wg0 --no-pager
ip -br addr show wg0
sudo wg show

اگر فایل تنظیمات را بعداً ویرایش کردید، برای اعمال تغییرات در زمان مناسب:

sudo systemctl restart wg-quick@wg0
ری‌استارت WireGuard ممکن است اتصال VPN را موقتاً قطع کند. اگر تنها راه دسترسی به VPS از طریق همین VPN است، پیش از ری‌استارت کنسول مدیریتی جایگزین آماده کنید. از SaveConfig = true بدون شناخت اثر آن استفاده نکنید؛ ممکن است فایل دستی را هنگام توقف بازنویسی کند.

برای بررسی فعال شدن خودکار پس از بوت:

sudo systemctl is-enabled wg-quick@wg0

خروجی مطلوب: enabled.

بررسی قانون Forwarding روی VPS

sudo iptables -C FORWARD -i wg0 -o wg0 -s 10.50.0.0/24 -d 10.50.0.0/24 -j ACCEPT && echo 'Forwarding OK'
sudo iptables -L FORWARD -n -v --line-numbers

۸. تست ارتباط، به ترتیب

از خانه:

ping -c 4 10.50.0.1

از شرکت:

ping -c 4 10.50.0.1
ping -c 4 10.50.0.2

بررسی Handshake در هر سیستم:

sudo wg show

در خروجی به latest handshake، transfer و allowed ips توجه کنید. اگر Ping شرکت به VPS برقرار است اما به خانه نه، از تست بسته‌ها در بخش عیب‌یابی استفاده کنید.

تست MTU (درس مهم سناریوی واقعی)

ping -c 4 -M do -s 1200 10.50.0.2

بسته با اندازه داده ۱۲۰۰، با سربار IPv4 و ICMP در مجموع ۱۲۲۸ بایت است. در تجربه ما بسته ۱۳۲۸ بایتی با پیام Frag needed and DF set (mtu = 1320) رد شد و SSH در تبادل کلید گیر می‌کرد. تنظیم MTU = 1280 روی اینترفیس WireGuard شرکت مشکل SSH را برطرف کرد؛ برای استقرار پایدار، این مقدار در تنظیمات هر سه گره پیشنهاد شده است.

MTU مناسب در همه شبکه‌ها لزوماً ۱۲۸۰ نیست. این مقدار یک انتخاب محافظه‌کارانه و تست‌شده برای سناریوی ماست. اگر محیط دیگری دارید، MTU را متناسب با مسیر خود اندازه‌گیری کنید.

۹. فعال‌سازی SSH روی خانه و اتصال از شرکت

روی خانه:

sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo ss -lntp | grep ':22'

روی شرکت:

ssh -o ConnectTimeout=8 roham@10.50.0.2

اگر اتصال برقرار شد، می‌توانید ورود مبتنی بر کلید را فعال کنید. روی شرکت:

test -f ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519
ssh-copy-id -i ~/.ssh/id_ed25519.pub roham@10.50.0.2
ssh roham@10.50.0.2

در صورت نیاز به ارسال فایل نصب از شرکت به خانه:

scp ~/Downloads/nomachine*.deb roham@10.50.0.2:/home/roham/

۱۰. ریموت دسکتاپ Ubuntu از طریق VPN

در سناریوی اجراشده، دسکتاپ خانه GNOME با نشست Wayland بود. روش موفق، استفاده از قابلیت GNOME Remote Desktop (Desktop Sharing) در خانه و Remmina در شرکت بود.

روی خانه

  1. به محیط گرافیکی خانه وارد شوید.
  2. در Ubuntu مسیر Settings → System → Remote Desktop (یا در برخی نسخه‌ها Settings → Sharing) را باز کنید.
  3. Desktop Sharing و در صورت وجود Remote Control را فعال کنید.
  4. نام کاربری، رمز RDP و پورتی را که تنظیمات نشان می‌دهد بررسی کنید.

روی شرکت

sudo apt install -y remmina remmina-plugin-rdp

در Remmina یک اتصال RDP با آدرس 10.50.0.2:3389 بسازید؛ اگر در تنظیمات خانه پورت دیگری نمایش داده می‌شود، همان را وارد کنید. اطلاعات ورود RDP ممکن است با نام کاربری/رمز ورود Ubuntu متفاوت باشد.

برای اشتراک‌گذاری همان نشست دسکتاپ، ممکن است لازم باشد کاربر خانه وارد GNOME شده باشد. قابلیت «Remote Login» و «Desktop Sharing» در نسخه‌های مختلف Ubuntu رفتار متفاوتی دارند. همچنین Sleep/Suspend سیستم خانه را برای دسترسی پایدار مدیریت کنید.

در این تجربه، نصب NoMachine Personal Edition 10.2.3 به پیام No subscription found on this server منتهی شد؛ بنابراین برای مستند قابل تکرار، مسیر رایگان GNOME RDP + Remmina ترجیح داده شده است.

ردیابی بسته روی VPS

sudo tcpdump -ni wg0 'icmp and (host 10.50.0.2 or host 10.50.0.3)'

ردیابی بسته روی خانه

sudo tcpdump -ni wg0 'icmp and host 10.50.0.3'
sudo tcpdump -ni wg0 'host 10.50.0.3 and tcp port 22'

مسیر برگشت و وضعیت Peerها

ip route get 10.50.0.3
sudo wg show
sudo ss -lntp | grep ':22'

اگر در tcpdump خانه فقط بسته‌های SYN دیده می‌شوند، پاسخ TCP را در مسیر برگشت و فایروال بررسی کنید. اگر هیچ بسته‌ای روی خانه دیده نمی‌شود اما VPS درخواست را دریافت می‌کند، Forwarding و قوانین VPS را بررسی کنید.

۱۲. امنیت، نگهداری و چک‌لیست نهایی

  • کلید خصوصی هر دستگاه فقط روی همان دستگاه نگهداری شود؛ فایل‌های private.key و wg0.conf مجوز 600 داشته باشند.
  • روی VPS برای هر Peer از AllowedIPs اختصاصی /32 استفاده کنید.
  • فقط UDP پورت WireGuard را روی IP عمومی VPS باز کنید؛ SSH و RDP خانه را به اینترنت عمومی معرفی نکنید.
  • در شبکه سازمانی، استفاده از VPN را با سیاست‌های امنیتی شرکت تطبیق دهید.
  • بعد از تغییر کلید یا فایل پیکربندی، وضعیت Handshake و اتصال عملی را مجدداً تست کنید.
  • در صورت تغییر IP عمومی VPS، مقدار Endpoint در خانه و شرکت باید اصلاح شود؛ استفاده از DNS ثابت مدیریت را ساده‌تر می‌کند.
  • برای جلوگیری از قطع دسترسی، Sleep/Suspend خانه و خاموش شدن خودکار سیستم را بررسی کنید.

چک‌لیست نهایی

  • ☐ سرویس wg-quick@wg0 روی هر سه سیستم enabled است.
  • ☐ آدرس‌های تونل .1، .2 و .3 درست و یکتا هستند.
  • ☐ VPS دارای net.ipv4.ip_forward=1 دائمی است.
  • ☐ قوانین PostUp/PostDown روی VPS ذخیره شده‌اند.
  • ☐ MTU روی هر سه سیستم متناسب با مسیر تنظیم شده است (در این سناریو 1280).
  • ☐ Ping شرکت به خانه و SSH موفق است.
  • ☐ Remmina از شرکت به دسکتاپ خانه از طریق IP خصوصی متصل می‌شود.
  • ☐ پس از ری‌استارت کنترل‌شده سرویس WireGuard، اتصال دوباره برقرار می‌شود.
نتیجه: با این معماری، بدون IP ثابت خانه و بدون انتقال پروژه‌ها بین دو سیستم، می‌توان از شرکت به محیط کاری واقعی خانه دسترسی داشت. تمام ترافیک مدیریتی بین دستگاه‌ها از تونل WireGuard عبور می‌کند.
